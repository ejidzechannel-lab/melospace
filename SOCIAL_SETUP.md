# Общая лента MeloSpace

## Включение
1. В Supabase SQL Editor выполнить `supabase/migrations/20261111_social_feed.sql`. Предыдущая миграция синхронизации должна быть уже выполнена.
2. Заменить код `melospace-api` файлом `supabase/functions/melospace-api/index.ts`, опубликовать. Health endpoint должен показывать version 7.
3. JWT gateway остаётся выключенным: записи проверяют подписанный Telegram initData, а чтение только опубликованных постов открыто всем.
4. Открыть приложение через бота. В медиатеке возле серверного трека нажать стрелку публикации. Подтвердить права на распространение и нажать «Опубликовать для всех».

## Поведение
Старые загрузки остаются приватными. Только владелец может явно опубликовать свой серверный трек. Имя из Telegram и подпись публикуются вместе с ним. Локальные файлы и Audius автоматически не публикуются. Чтение постов, комментариев и воспроизведение опубликованной записи доступны без входа. Лайки, комментарии и внутренние репосты требуют подписанной сессии Telegram. Репост поднимает исходный пост в общей ленте и показывает имя последнего поделившегося; исходное авторство сохраняется. «Поделиться» открывает выбор получателя в Telegram и само по себе сообщения не отправляет. Комментарии выводятся текстом, HTML не исполняется.

## Снятие и жалобы
Автор может снять свою публикацию и удалить свой комментарий. При снятии новые ссылки на аудио не выдаются, но ранее выданные ссылки действуют до пяти минут. Сам личный файл и социальные записи не удаляются автоматически.

Жалобы сохраняются в `public.music_post_reports`. Администратор должен регулярно проверять эту таблицу через Supabase Table Editor. Для снятия спорного контента у соответствующего `music_posts.id` выставить `status = hidden`. Автор не сможет самостоятельно восстановить скрытую модератором публикацию. Комментарий можно скрыть установкой `deleted = true` в `music_post_comments`. Эти операции не удаляют файл из личной медиатеки.

При необходимости добавить секрет `MELO_ADMIN_USER_ID`: числовой ID Telegram администратора. Серверный action `moderate` доступен только этому ID; интерфейс панели модератора пока не реализован. Никому не выдавать service_role или секреты бота. У таблиц включён RLS, клиентского прямого доступа нет.

Это первая версия общей ленты: есть простое ограничение частоты комментариев, но нет полноценных антиспам-фильтров и очереди премодерации. Публичные прослушивания используют исходящий трафик Supabase; следить за Free-квотами в Dashboard → Usage.

## Проверка после установки
На двух разных Telegram-аккаунтах проверить: приватный трек отсутствует у второго; после публикации виден обоим; воспроизведение; лайк/снятие лайка; комментарий/удаление только своего; репост/отмена; снятие публикации; жалоба и ручное скрытие.
